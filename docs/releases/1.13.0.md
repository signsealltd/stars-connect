# V1.13.0 — Management Tasks workspace

Version: V1.12.2 → V1.13.0. No schema or data migration is required.

The dashboard Tasks link continues to open `/dashboard/staff/tasks`. This release
replaces the two competing lists with one accessible queue, real filtered summary
counts, search, owner/priority/due filters, advanced status/source filters and
incremental rendering of 20 records. Urgent, overdue and decision work sorts first;
ties have stable identifiers. Staff requests, system reminders, premises actions,
compliance actions and event confirmations retain their distinct sources.

## Records and history

- Each permitted contact-detail save currently writes a separate completed PROFILE
  request with a new identifier and before/after values. These are audit snapshots,
  not automatically duplicates. All remain available under Completed with descriptive
  subjects, submission timestamps and read-only details. No records are merged/deleted.
- Saving a billing period upserts one reminder by `billing-period:<id>`; funded runs
  also upsert payer-specific reminders. Issuing or paying invoices does not reliably
  close those reminders. Unresolved billing reminders whose period ended before the
  current London calendar month appear in Billing history and All tasks, with their
  original OPEN status. A visible history count explains their exclusion from My focus.
  Resolved records appear in Completed. No payment state or audit record is changed.
- Evidence attachments already linked to compliance actions and asset documents are
  exposed in details. Evidence-dependent completion stays in the original workflow;
  there is no new generic completion endpoint. Awaiting information is distinguished
  from the explicit Awaiting evidence status. No new evidence upload workflow is added.
- Staff event/training creation, editing, cancellation and response acknowledgement
  remain available. Pending confirmations join the queue and have a separate expandable
  section. Confirmed/reviewed responses are excluded from active counts.

## Access and calculations

The page and APIs require Tasks access. Staff-request review capability, organisation,
medical-data and conflict-of-interest restrictions remain enforced server-side. Each
system source is filtered by its existing capability. Compliance actions additionally
require compliance view/action management and sensitive access for linked records.
Task details expose only permitted sources; download endpoints retain their checks.
The existing global operational/premises models have no organisation column; this
release preserves their existing application scope rather than inventing tenancy.

Summary counts use the selected view and filters, before the 20-row display limit.
Needs my decision includes authorised unassigned or personally assigned open requests
and relevant event responses/verification actions. Due this week means today through
Sunday in Europe/London. Failed feeds show an error and suppress partial summary numbers.
The refresh control reloads data; this is not a push-notification/live-stream service.

## Business decisions remaining

Agree when a billing reminder may close automatically (for example, all intended
invoices issued, versus explicit management confirmation). Invoice payment is a
separate workflow and cannot be inferred. Historical unresolved periods remain visible
until reviewed. An evidence upload/verification workflow for generic operational tasks
would be a separate feature; supported source documents are linked here today.

## Validation

Focused tests cover subjects, retained distinct submissions, decision ownership,
confidential summaries, stable ordering, real counts, terminal states and London dates.
Browser checks against a disposable database cover creation, request review, read-only
completed records, unresolved billing history, denied users and responsive overflow at
1440px, 820px and 390px. Desktop/tablet screenshots show synthetic records filtered by
“Monday review”; displayed counts come from those database rows, not the design mockup.

Validation result: 641 non-database tests passed; all 31 database tests passed after restarting the disposable database (672 total across 130 files). Changed-file ESLint passed. Browser checks passed at desktop, tablet and phone sizes.
Production build passed with existing warnings only. Final screenshots were captured from the production build against the local disposable database.
