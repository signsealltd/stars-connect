# V1.19.0 — Safety & Compliance workspace

## Changes

- Rebuilt the overview around a shallow Clive banner, permission-aware module navigation, real metrics and filtered attention rows. Existing global STARS branding and navigation remain in place.
- Added full-page policy registers, editors and readers. Tiptap supports headings, emphasis, links, alignment, nested lists and tables, including conversion of Word's styled list paragraphs. Server-side sanitisation removes unsafe HTML. Drafts have unsaved-change protection and stale-save checks.
- Preserved immutable publications, separate revisions, approval controls and historical attachments. Workflow actions identify the exact version/update time reviewed. Staff continue to read the previous publication while a draft is prepared.
- Added full-page staff policy/RAMS reading with contents, exact-version acknowledgement, print/Save PDF and historical receipts. Reports include superseded versions and retained receipts for staff who have changed role or left. New publication audiences retain individual recipient assignments alongside the existing group rules and notifications.
- Added a private printable PDF library with search/categories, upload, preview, browser printing, download, stable replacement links, administrator version history and independently editable staff visibility. Blank forms do not require acknowledgements. Existing training certificate and staff request document endpoints are unchanged.
- Consolidated aggregate checks and historical inspections into Asset Register, with Overview, Tests & inspections, Documents and History tabs. Legacy inspection navigation redirects into the checks view. Calendar and overview count individual active schedules rather than duplicating the asset's earliest date. Existing numbering, QR tokens, DYMO/A4 label generation and profiles remain intact.
- Added explicit asset publication state. Newly published assets default to public QR viewing unless an explicit privacy choice exists; hidden/unpublished records and their public files are unavailable. Existing field allowlists, approved public locations, private-field exclusion and no-store responses remain enforced.
- Added separate Insurance and RIDDOR routes alongside existing COSHH and Fleet. Existing classified records, attachments and permissions are retained.
- Reworked RAMS into a compact register and dedicated full-page drafting/reading, with version selection, owner, review dates, acknowledgement progress and copying an existing RAMS into a fresh draft. Existing structured hazards, scoring, Clive draft acceptance, approval, publication and branded PDF generation are preserved.

## Deployment

1. Back up the database and private uploads using the existing deployment process.
2. Install the committed dependency lockfile with npm ci.
3. Run npx prisma migrate deploy before starting this version, then generate Prisma/build and restart using the existing deployment process.
4. Retain the existing private compliance storage directory/volume and its permissions. No new external service or credential is required. Public asset links continue to require the existing HTTPS public-base-URL configuration.

Migration: 20261014010000_safety_workspace.

The migration only adds asset publishedAt/publicChoiceAt columns and PrintableDocument/PrintableDocumentVersion tables. Existing enabled public assets are treated as published. Existing publication audit events preserve explicit visibility choices. Previously hidden assets without evidence of publication remain unpublished; the migration does not infer permission to expose them. No records, attachments or tokens are deleted, reset or seeded.

Policy HTML and change summaries use existing structured version storage. Previously plain-text policies are escaped on display. New PDF uploads use existing private file storage and audit conventions.

## Limits / deployment acceptance

- No live database migration, production deployment or live staff workflow was performed from this checkout. Verify an authorised publish/acknowledge flow and PDF replacement on staging before deployment.
- Policy PDF output uses the browser's Print / Save PDF with A4 print styling and natural page flow; it is not a separate server-rendered PDF service. Native printer/PDF-dialog pagination was not exercised by the available browser test interface. Check a representative long Word policy on the deployment browser before publishing it. RAMS retains its existing branded server PDF.
- Word images, text boxes, headers/footers, tracked changes and fixed page layouts are explicitly unsupported by rich-text paste. The editor explains this and allows the original document to be attached. Semantic text, lists and tables are retained.
- PDF thumbnails/page counts are not extracted; cards provide authenticated PDF preview instead.
- Historical group-only assignments created before this release cannot reconstruct past role membership. Existing receipts are retained; individual publication-recipient snapshots apply to new publications.
