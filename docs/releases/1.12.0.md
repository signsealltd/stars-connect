# STARS Connect V1.12.0

Previous version: V1.11.1. Feature release: V1.12.0.

## Delivered

- Tasks combines existing staff requests, attendance responses, operational/system tasks and premises corrective actions; medication tasks open the restricted medication workflow.
- Medication stock links to existing clients, preserves legacy care notes, supports daily or weekday usage, decimal quantities and manually estimated PRN usage. Paused/discontinued/invalid records do not create run-out alerts. All projected quantities/dates are labelled estimates; confirmation age is visible.
- Counted stock, deliveries, corrections and unused scheduled quantities append stock history. One prescription task per reminder cycle progresses through request/awaiting/ready and completes on a counted receipt. Priority escalates at seven and three days and after projected run-out; default lead time is 14 days. Repeat checks/notifications are deduplicated. Corrected estimates can become due again in a new cycle.
- Medication overview filters, client-profile links, dashboard summary/notifications, Tasks and an authorised Staff Area route share one backend.
- Structured staff personal/address/emergency contacts, employment extensions and separately permissioned health/occupational-health information. Existing employment/payroll/schedule fields stay in their original controls.
- Staff can submit personal/health changes without updating the approved record. Authorised managers see readable before/after values, approve/reject, retain review/audit details and notify the employee. Existing low-risk name/phone edits remain direct and are also audited. Private request attachments retain their existing storage and access controls.
- Settings password resets no longer attempt to override linked staff access levels. Password policy is unchanged.

## Validation

- 650 tests passed across 127 files, including real disposable-MariaDB medication, HR, fleet and payment integration suites.
- Production build and TypeScript validation passed. Lint has no errors; 18 pre-existing warnings remain.
- Browser checks exercised medication creation, stock confirmation, prescription progress, staff submission, approval and rejection. Staff sessions could not access management HR or unpermitted medication routes; occupational-health notes were absent from staff responses.
- Browser layouts checked at 390, 820 and 1440 pixels without horizontal overflow; screenshots reviewed. Supporting test data exists only in the disposable local database.
- Additive migration applied successfully to the disposable database; legacy medication JSON remained intact.

## Deployment and permissions

Run `npx prisma migrate deploy` before starting the release. Apply migration `20260924120000_medication_stock_staff_hr`. Grant new capabilities to the intended custom access levels: existing custom permissions are not expanded silently. Administrators retain unlimited access; non-administrator staff medical view/edit grants are explicit.

The existing protected daily report job now checks medication reminders as well. Confirm that the existing scheduler is running. An independent POST `/api/cron/medication-reminders` endpoint uses `REPORT_JOB_SECRET` for installations without the report job. No remote scheduler was changed and no production database was accessed during implementation.

For rollback, stop the reminder job, restore the previous application build and leave the additive schema/data in place. Take a verified backup before deployment. Do not drop the new audit/data tables or overwrite subsequent production data with an old backup. See README for calculation, permission and operational details.

Legacy free-text dose information deliberately needs human confirmation before estimation. This release does not add clinical dose interpretation, electronic medication administration, pharmacy integrations, email/SMS reminders or a separate management-only document-upload system. Supporting files use existing private request attachments.
